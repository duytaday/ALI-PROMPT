# Definition of Ready

A task is ready for implementation only when all applicable items are complete:

- [ ] Target user, problem, evidence, and desired measurable outcome are stated.
- [ ] Scope and non-scope are explicit.
- [ ] Acceptance criteria are observable and include negative/permission cases.
- [ ] One DRI, one approver, consulted roles, and allowed write paths are assigned.
- [ ] Current behavior is evidenced from the repository or explicitly unknown.
- [ ] UX flow and state requirements are defined.
- [ ] Domain invariants and architecture decision are approved when material.
- [ ] Prompt-product type, variables, version, compatibility, preview, license, and eval impact are defined when applicable.
- [ ] Auth, payment, entitlement, PII, secret, abuse, and prompt-injection impact are classified.
- [ ] Analytics requirements and prohibited properties are specified.
- [ ] Dependencies, migration, rollout, rollback, and support impact are known.
- [ ] Required test evidence is specified.
- [ ] Open questions are non-blocking or explicitly accepted by the correct approver.
